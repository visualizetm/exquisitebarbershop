REPORT 09: THE API CRASHED ON VERCEL BEFORE ANY CODE RAN
Branch claude/p9-vercel-function-fix from claude/p8-showcase-demo (PR 3 was not merged). Commits and PR: see the pull request.
Fix, option A: the API is one esbuild bundle (server/bundle/app.mjs, committed, rebuilt by npm run build and checked fresh in CI) behind a plain-JS function file api/index.js that answers JSON FUNCTION_LOAD_FAILED if the bundle cannot load. B (.js extensions on about 230 files, NodeNext) was rejected: it touches every file and relies on Vercel compiling each one the way I hoped.
Broken: api/[...path].ts imported ../server/http/app with no extension (ERR_MODULE_NOT_FOUND, reproduced exactly under plain node). Found while testing: Vercel routes api/[...path] as one path segment (^/api/([^/]+)$), so nested paths such as /api/auth/login, /api/staff/marcus, /api/admin/* and the cron path would have 404'd; the function is now api/index.js with the rewrite /api/(.*) to /api. Also fixed: the tracer packed .data/uploads into the function.
Proof: npm run test:vercel-function, 89 checks, plain node, only traced or `vercel build` files: no env gives JSON { ok:false, missing }; the showcase env on an empty database auto-sets-up, health ok, shop 200, demo login, GridFS upload and GET /api/media/:id; missing bundle gives JSON FUNCTION_LOAD_FAILED; Vercel's routing table sends every /api path to the function and pages to index.html.
Fails when broken (each run exit 1): extensionless import in api/index.js, 15 failures (trace cannot find the bundle); rewrite removed from vercel.json, 14 failures (every /api path 404); an import to a missing file in server/, esbuild "Could not resolve". All restored; green again.
Wrong in reports 05 to 08: every statement about production behavior (env gate, /api/health, setup, demo mode, "root cause" of the down screen) was never observed on Vercel; reproductions ran under tsx, which resolves extensionless imports. Correction notes added to those reports.
Not proven here: that Vercel passes the original path to the function after the rewrite (the standard Express-on-Vercel pattern relies on it). The first deploy's /api/health and /api/staff/marcus confirm it. The Vercel API refused this session (403), so the failed deployment itself could not be inspected.
